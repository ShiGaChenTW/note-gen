# Phase 3 規格：首頁、知識報告、對話摘要、Agent 任務中心

> 術語以根目錄 `GLOSSARY.md` 為準；架構取捨見 `docs/adr/0001`（任務中心）、`docs/adr/0002`（記憶留在 SQLite）。概念參考 codex-echoink 2.8.4 的工作台與首頁（研究報告 `~/Documents/REA-Research/codex-echoink/`），只借概念，不抄程式碼，PRO 範圍（記帳、英文日記、PDF 精讀、會員）一律不碰。

## 0. 目標

note-gen 取代桌面版 Obsidian，成為 Scott 的第二大腦、筆記與日程主力工具。vault 繼續與 Obsidian 相容（手機仍用 Obsidian），不寫入 Obsidian 讀不懂的格式。

本階段交付四件事：

1. **首頁**：啟動後的全畫面中心，由可開關的首頁卡片組成。
2. **知識報告**：定期分析 vault，告訴 Scott 每個主題的掌握度與可以深化的地方。
3. **對話摘要**：一鍵把一次 AI 對話收斂成筆記，作為報告的證據。
4. **Agent 任務中心**：讓 AI 在背景執行多步驟工作，結束後由 Scott 彙整審核。

## 2. 首頁

### 2.1 進出

- 啟動後顯示全畫面首頁（不是分頁）。`currentPage` 新增首頁路由；舊值 `/core/main` 仍可用，但預設改成首頁。
- `⌘⇧H` 在首頁與工作區之間切換。點首頁上的任何項目，都會進工作區並打開該項目。
- Today 分頁退役：`openTodayTab()` 與相關指令改成開首頁的日程卡片。資料邏輯（`use-today-data.ts`）移給日程卡片使用，同一份資料不會出現在兩個地方。

### 2.1a 版面（原型定案：版型 D，2026-10-26）

原型比較了 A Bento 卡片牆、B 收件匣工作台、C 今日時間軸、D／E 兩種 B+C 組合，Scott 選 **D**。原型放在分支 `prototype/phase3-home`（`src/app/prototype-home/`，用 `?variant=D` 開啟），不併入 dev。

- **頂部**（取自 C）：日期與摘要（行程數、待辦數、需要你處理幾項）、`⌘⇧H`、編輯首頁；指令列（Enter 記一筆存進 Inbox，⌘Enter 交給 Agent，⌘K 搜尋）；一排主題掌握度膠囊，點了開完整報告。
- **主欄**（取自 B）：「需要你處理」單一清單，把待審草稿、沒做完的任務、逾期待辦、優化建議、規則提醒、未摘要對話合併成一份，每項附一個動作按鈕（審核／繼續／完成／交給 Agent／摘要）。下方接背景任務的四組狀態。
- **右欄**（取自 C）：今日時間軸，把行程、有時間的待辦、Agent 任務完成的時點排在同一條線上，有一條「現在」線；接著是沒有時間的待辦、最近筆記、本週足跡、知識庫健康。
- 首頁卡片的開關在這個版面上的對應：日程＝時間軸與待辦；知識報告＝主題膠囊與優化建議；可以交給 Agent＝清單裡的提醒；快速記錄＝指令列；Agent 任務＝清單裡的草稿／沒做完、背景任務區與未摘要對話。
- 審核草稿、完整報告、對話摘要預覽一律以右側抽屜開啟，畫面照原型。

### 2.2 首頁卡片

每張卡片都能開關、拖曳排序。設定存在 app 端（Tauri store），不進 vault。首頁右上角有「編輯首頁」。

| 卡片 | 預設 | 內容 |
|---|---|---|
| 日程 | 開 | 原 Today 的內容：逾期／今日任務、EventKit 今日行程、⏰ 提醒；快速新增待辦（Obsidian Tasks 格式，寫進今日每日筆記） |
| 知識報告 | 開 | 最新一期的重點：掌握度變化最大的主題、前 3 條優化建議、「立即產生」按鈕；還沒有基準時顯示「建立基準」 |
| 可以交給 Agent | 開 | 依規則算出的提醒（§2.3），先顯示 5 條，可以展開 |
| 快速記錄 | 開 | 一行輸入，每則存成 `Inbox/` 裡的一則新筆記（資料夾可在設定改） |
| 最近筆記 | 開 | 最近修改的筆記，最新一篇顯示成大卡片並附摘要 |
| Agent 任務 | 開 | 分成等你回應／進行中／沒做完／今天完成；另列最近對話，還沒摘要的對話旁顯示「摘要」按鈕 |
| 本週足跡 | 關 | 每天寫下／修改／重讀的次數；紀錄存在 app 端，只記路徑、事件與時間 |
| 知識庫健康 | 關 | 缺少連結、孤立筆記、Inbox 積壓的數字，直接取自最新一期知識報告的統計 |

### 2.3 「可以交給 Agent」規則

每條都能個別開關，門檻可以調整：

- 待辦逾期；逾期超過 3 天
- 晚上 18 點後今天還沒寫每日筆記；連續 3 天沒寫
- `Inbox/` 有 3 則以上，或有一則放超過 72 小時
- 5 篇以上筆記缺少連結
- 週五晚上到週日還沒做本週複盤
- 最新一期知識報告還有未處理的優化建議

按「交給 Agent」會建立一個 Agent 任務並預填指令，Scott 按「開始」才真的執行。

## 3. 知識報告

### 3.1 主題

- 報告以**主題**為評估單位。主題清單優先取現有的標籤與 MOC；沒有歸到任何主題的筆記，由 AI **提議**新主題，Scott 確認後才列入。
- 清單固定下來，每期沿用，才能比較趨勢。新增、合併、改名都由 Scott 操作。
- 存放位置：vault 裡的一則清單筆記（例如 `報告/主題清單.md`），Obsidian 也看得到、可以改。
- 格式（#34 定案）：每個 `## 名稱` 是一個主題，底下 `- 標籤：#a、#b`、`- MOC：[[x]]`、`- 資料夾：A/B`、`- 筆記：[[y]]` 任一符合就算在主題裡；`- 狀態：待確認` 是還沒確認的提議，刪掉那一行就是確認；其他行原樣保留。

### 3.2 掌握度

- 分數由**行為訊號**用公式計算，AI 不自評：寫了多少、用自己的話改寫過幾次、連結密度、回顧間隔、有沒有總結或 MOC、對話摘要中「我的觀點與理解」、相關的 `active` 記憶。
- 內部用 0–100 的分數，畫面上只顯示四個等級：**接觸**（只有摘抄）、**整理**（有結構）、**內化**（有自己的觀點與改寫）、**融會**（跨主題連結，或實際用過）。
- 每個等級都附「離下一級還差什麼」，這也就是優化建議的來源。
- AI 只寫文字評語，每條評語都要附引用的原文與雙鏈作為證據。
- 公式的權重與門檻放在一個獨立、可測試的純函式模組，並附單元測試。

### 3.3 資料來源

- Markdown 筆記、每日筆記、PDF 文字（沿用既有的 RAG 擷取）。
- 對話摘要：只有「我的觀點與理解」算進「內化」，「AI 的解答重點」只算「接觸」。
- SQLite 記憶：只讀 `active` 狀態。preference 與 decision 用來調整主題優先順序；experience 是低權重的加分；引用時標明出處。不寫回記憶（ADR 0002）。
- 不讀對話全文。圖片、音訊、附件不在本階段範圍。
- 設定中可以排除指定資料夾，被排除的內容永遠不送給模型。

### 3.4 產出

- 存成 vault 筆記 `報告/YYYY-Www 知識報告.md`。內容：各主題的等級與變化、AI 評語與證據、優化建議清單、統計（給知識庫健康卡片用）。
- 優化建議只是清單，例如「這 5 篇講同一件事，可以合併」「這個主題只有摘抄、沒有自己的觀點」「缺少和 X 主題的連結」。每條都有「交給 Agent」按鈕，處理狀態記錄在報告筆記內。
- 報告本身絕不修改其他筆記。

### 3.5 頻率與成本

- 預設每週一次，可以改成每天或每月。app 開著時定期檢查是否到期，到期就以 Agent 任務的形式在背景產出，完成後發出通知。首頁另有「立即產生」按鈕。
- 第一次不自動執行，流程是「建立基準」：整理主題清單 → Scott 確認 → 顯示 token 估算 → Scott 按開始。
- 之後每期只分析增量：上一期之後有變動的內容，加上每個主題的摘要快取。
- 報告使用的模型可以另外設定，預設沿用 note-gen 的預設模型，也可以改用本機 Ollama。每次產出前估算 token，超過上限就暫停，等 Scott 確認。

## 4. 對話摘要

- 按鈕放在對話標題列。按下後先顯示預覽，內容和路徑都可以改，按「存檔」才寫進 vault。
- 存放位置：`對話摘要/YYYY/MM/YYYY-MM-DD <主旨>.md`。
- 對話裡掛的連結資源，以及對話中提到的筆記，都以**雙鏈**寫在「相關筆記」一節。
- 固定分節：我的問題／我的觀點與理解（只收 Scott 自己說的）／AI 的解答重點／結論與決定／還沒解決的問題／相關筆記。
- frontmatter：`type: 對話摘要`、對話 id、日期、相關主題。
- 同一個對話再按一次，會更新同一份摘要（以對話 id 對應），不另開新檔。存檔後就是一般筆記，報告讀的是 Scott 改過的版本。
- 原本「單則回覆存成筆記」的功能保留。

## 5. Agent 任務中心（ADR 0001）

### 5.1 範圍

以下四種工作都走同一個任務中心：產出知識報告、執行優化建議、「可以交給 Agent」的規則提醒、在對話中把指令「丟到背景」。

### 5.2 架構

- 由 fork 自建任務中心，重用 `AgentRuntime` 與權限引擎，透過 `AgentStateAdapter` 讓每個任務各有一份狀態。上游的 `chat-send.tsx` 與 `useChatStore` 不動。
- 新增任務表，模式比照 `memory_jobs`：id、類型、指令、狀態、草稿、token 用量、錯誤、時間戳。
- 狀態：等你回應、進行中、沒做完、已完成（另有已取消）。

### 5.3 寫入審核

- 任務執行中的所有修改都先存成**草稿**，不寫進 vault。任務結束後進入「等你回應」，Scott 看一份彙整的差異清單，可以全部收下、逐條收下或全部丟掉。
- 刪除與搬移檔案一律逐條確認，不能整批收下。
- 收下之前，vault 完全不變。
- 例外：知識報告任務只新增報告筆記（以及更新主題清單裡由 Scott 確認過的項目），直接寫入。

### 5.4 執行限制

- 同時最多執行 2 個任務，其他排隊；上限可以在設定調整。
- 每個任務都能取消（`AbortController`），並顯示已用的 token。
- 關閉 app 時，進行中的任務標成「沒做完」並保留草稿；下次啟動時，首頁顯示「繼續」，從已存的草稿與紀錄重新啟動任務。「等你回應」的任務照樣等待，不會遺失。
- 有任務進入「等你回應」或完成時發出系統通知（沿用 `approval-notification.ts`）。

## 6. 建議拆分（約 6 個 PR）

1. **任務中心核心**：任務表、執行器、狀態轉接器、草稿與審核流程、取消、重啟後「沒做完」。先做，其他項目都依賴它。
2. **首頁骨架**：路由、`⌘⇧H`、卡片框架、開關與排序；把 Today 搬成日程卡片並退役 Today 分頁。
3. **首頁卡片**：快速記錄、最近筆記、本週足跡、Agent 任務卡（含最近對話與「摘要」按鈕）、「可以交給 Agent」規則。
4. **對話摘要**：標題列按鈕、預覽與修改、存檔或更新、雙鏈。
5. **知識報告 (1)**：主題清單、掌握度公式（純函式加測試）、資料來源擷取與增量快取。
6. **知識報告 (2)**：建立基準流程、報告筆記、成本估算、排程、知識報告卡與知識庫健康卡、優化建議交給 Agent。

## 7. 不在本階段

echoink 的 vault 記憶與做夢、`/maintain` 知識整理、PRO 功能（記帳、英文日記、PDF 精讀）、測驗式評估、分析圖片與音訊、系統常駐程序或 cron、寫入 EventKit 或 Reminders、修改上游的對話元件與記憶模組。

## 8. 待確認與風險

- 掌握度公式的權重需要先用 Scott 的真實 vault 校準，第一版的數字只是起點。
- 主題清單筆記的格式已在 #34 定案（見 §3.1）。
- `AgentRuntime` 是上游程式，上游改了它的介面，任務中心就要跟著改；同步上游時要列為檢查項目，並記在 `personal/FORK-CHANGES.md`。
- 增量分析的「有變動」判斷沿用 vault 索引的 mtime；如果手機在 app 關閉期間大量修改，下一期的成本會變高。
- 草稿和 vault 之間可能衝突：任務執行期間，Scott 或手機修改了同一份檔案。收下前要先比對，衝突的項目改為逐條確認。

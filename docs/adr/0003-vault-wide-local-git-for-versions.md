# 整個 vault 用一個本機 git repo 管理版本，與遠端同步分開

個人提示詞庫需要可回顧、可回復的版本。我們在 vault 根目錄使用本機 git repo（Rust 端嵌入 git），而不是借用現有 GitHub/Gitee/GitLab/Gitea 同步的遠端 commit 歷史，也不是自行在 app 內存快照。理由：遠端歷史只有選 git 類同步平台、且連線時才有，commit 粒度也不由我們控制；本機 git 可離線、粒度由「確認儲存」等動作決定，且沿用使用者熟悉的工具。

範圍取整個 vault 而非只有提示詞資料夾：之後一般筆記也能看歷史，掌握度的行為訊號也能從歷史取得；巢狀 repo 或路徑限制都更難維護。預設只追蹤文字檔（`.md`、`.canvas`、`.base`），附件不追蹤以免 repo 膨脹。vault 若已有 `.git`（例如 obsidian-git）就沿用，不重建、不搶它的工作。

本機 git 只負責版本，不取代既有同步：REST 同步不讀 `.git`，兩者並存；`git push` 是否成為一種同步方式另議。

替代方案：(1) 沿用遠端同步歷史——受限於平台與連線；(2) app 內快照——自造輪子、外部工具看不到；(3) 只管提示詞資料夾的巢狀 repo——之後擴大範圍成本高。
